# Pacman

A neon-styled Pac-Man built in Python with pygame, developed as a
42 Common Core project.

## Description

This project recreates the classic arcade game Pac-Man, with a
procedurally generated maze (via an external `A-Maze-ing` package),
object-oriented game logic, a highscore system, cheat mode, and a
custom neon visual style with glow effects.

Features include:
- Procedurally generated mazes, with a "42" shaped landmark in
  the center
- A configurable number of pacgums, super pacgums, and levels
- Four ghosts with staggered activation, BFS-based pursuit (with
  a random chance of getting it wrong, so they're not perfect),
  and a fleeing behavior when edible
- A difficulty curve: ghosts get faster, smarter, and pacgums
  increase as levels progress
- Smooth, visually interpolated movement for the player and ghosts
- A full menu flow (welcome, menu, pause, level complete, game
  over/won, highscores)
- A cheat mode (speed boost, invincibility, level skip)
- Persistent, validated JSON configuration and highscores
- Two ghost skins, switched with the arrow keys on the menu:
  "Politically correct" and "Unhinged" (anonymous, censored
  42 staff ghosts)

## Instructions

### Requirements
- Python 3.12 or 3.13 (pygame has no precompiled wheel for newer
  versions, and compiling it from source requires system libraries
  that may not be available)
- The `mazegenerator` package, provided as a `.whl` in `vendor/`

### Install and run

```bash
make venv      # creates a .venv using python3.12 or python3.13
make install   # installs dependencies and the mazegenerator package
make run       # starts the game using config.json
```

No manual venv activation is needed — every Makefile rule uses the
venv's own interpreter directly.

### Other Makefile commands

```bash
make debug        # run with Python's debugger (pdb)
make lint         # flake8 + mypy (standard)
make lint-strict   # flake8 + mypy --strict
make clean        # remove caches and compiled files
```

### Controls

| Key | Action |
|---|---|

| C | Toggle cheat mode |
| N | Skip to next level (cheat mode only) |
| Enter | Confirm / start |
| Q | Quit |
| M | Toggle music (menu) / return to menu (pause, highscores) |

## Configuration

The game reads a JSON config file (e.g. `config.json`), passed as
the program's only argument. Lines starting with `#` are treated
as comments and ignored.

Every value is validated on load; missing or invalid values fall
back to a safe default, and the game never crashes on a malformed
config.

| Key | Default | Description |
|---|---|---|
| `lives` | 3 | Starting number of lives |
| `highscore_filename` | `"highscores.json"` | Path to the highscore file |
| `pacgum` | 42 | Base number of pacgums per level (scales up per level) |
| `points_per_pacgum` | 10 | Points for eating a pacgum |
| `points_per_super_pacgum` | 50 | Points for eating a super pacgum |
| `points_per_ghost` | 200 | Points for eating an edible ghost |
| `seed` | 42 | Seed for the first level's maze |
| `level_max_time` | 90 | Seconds allowed per level |
| `levels` | `[{"width": 21, "height": 21}]` | List of `{width, height}` per level |

## Highscore

Highscores are stored in a JSON file (path set by
`highscore_filename`), as a simple list of `{"name", "score"}`
entries, sorted and capped to the top 10. JSON was chosen for
simplicity: the team was already familiar with it from the config
system, and it avoids adding a database dependency for something
this small. Scores are loaded when needed and saved immediately
after a game ends (win or lose), so progress isn't lost if the
game is closed from the highscore screen.

## Maze Generation

Mazes are generated by the `mazegenerator` package, assigned to
this group and used as-is via its provided `.whl` file (installed
from `vendor/`, never modified or copied into `src/`). The
generator is called with `perfect=False`, as required by the
subject, to produce Pac-Man-compatible corridors with no dead
ends.

`maze_loader.py` adapts the package's raw output (a grid of
bitmask integers, where each bit marks a wall on one side of the
cell) into our own `Maze`/`Cell` objects, used by the rest of the
game.

## Implementation

The game is built with Python dataclasses for its core entities
(`Player`, `Ghost`, `Cell`, `Maze`, `Config`), pygame for
rendering and input, and a finite state machine (`AppState`) to
drive the menu/gameplay/pause/game-over flow.

Movement is visually interpolated between cells for smooth
animation, independent of each entity's actual (logical) grid
position — collisions are checked against this visual position so
they match what's on screen.

Ghost behavior combines BFS pathfinding (for active, non-edible
ghosts) with a configurable probability of moving randomly
instead, so pursuit isn't perfectly deterministic. Ghosts activate
progressively as pacgums are eaten, and difficulty (ghost speed,
pursuit accuracy, pacgum count) scales with the level index.

## General Software Architecture

pac-man.py — entry point: parses config, builds maze/player/game, runs the app

src/
- app.py — pygame app shell: window, event loop, all screens (App, AppState)
- game.py — core game rules: score, pacgums, ghosts, levels (Game, GhostMode)
- player.py — player entity: position, movement (Player)
- ghost.py — ghost entity: movement, edible/respawn state (Ghost)
- maze/
  - maze.py — Maze/Cell data model, BFS pathfinding (Direction, Cell, Maze)
  - maze_loader.py — converts MazeGenerator output into Maze/Cell
- config.py — config dataclasses and defaults (Config, LevelConfig)
- parsing.py — JSON config loading and validation
- display.py — all pygame rendering (maze, player, ghosts, HUD)
- graphics.py — low-level drawing helpers (glow, blur, interpolation)
- constants.py — colors, sizes, timing constants, loaded assets
- sounds.py — sound effects and music (Sounds)
- highscores.py — highscore persistence

`Game` owns and coordinates all gameplay state; `App` owns the
window and screen flow and calls into `Game` each frame. `display.py`
reads from `Game`/`Player`/`Ghost`/`Maze` to render, but never
mutates them.
